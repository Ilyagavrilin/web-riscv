Quick start

  1. Debugger: load an ELF or choose an assembly example.
  2. Use Clock +1, Instruction +1, or Run. Click an instruction to set a breakpoint.
  3. Devices: attach any peripherals required by the program, at the documented address.
  4. Diagnostics: enable capture before running; export JSON for the retained event log.

Load a bare-metal ELF

In Debugger, choose an ELF file or drop it into the loader. The file is saved in your browser's local ELF library. Nothing is sent to a server. Reload it from the library at any time, or remove the saved copy.

Use ELF32, little-endian, machine RISC-V, executable type ET_EXEC, with entry at 0x200. Every PT_LOAD segment must fit in 64 KiB RAM. BSS is zero-filled. The loader shows segment addresses, executable bytes, basic disassembly and any PC breakpoints you set. Unknown compressed encodings appear as .hword; the hardware still executes them.

Compile for the selected profile: -march=rv32imc -mabi=ilp32, -march=rv32ic -mabi=ilp32, or -march=rv32ec -mabi=ilp32e. Supply a linker script and startup code that initializes your stack. There is no operating system or syscall emulation. Write an exit code to 0xF0000004 to finish, or write bytes to 0xF0000000 for UART.

Changing profiles reloads the active image into a fresh CPU. Reset reloads the same ELF, even when the assembly editor contains different text.

Write a Wasm MMIO module

A peripheral is an independent Wasm instance. It receives register offsets and naturally aligned byte widths from accepted CPU data-bus requests. It does not import the CPU module or modify SCR1. Multiple instances can occupy different windows, including multiple instances of the same file.

SystemC device SDK

The example devices are real SystemC modules, linked against the pinned Accellera SystemC 3.0.2 kernel. Write C++17 register behavior and an SC_METHOD sensitive to clk.pos(). You do not write Wasm exports or manually call the clock method. 

#include <scr1/device.hpp>
class Counter final : public scr1::ClockedDevice<1> {
public:
  explicit Counter(sc_core::sc_module_name name) : ClockedDevice(name) {
    SC_METHOD(count);
    sensitive << clk.pos();
    dont_initialize();
  }
  void count() { ++registers_[0]; }
};
scr1::Device& scr1::device() noexcept {
  static Counter instance{"counter"};
  return instance;
}

read(index) may have side effects; inspect(index) const must not. write(index, value, mask) receives a word-aligned value and byte-lane bitmask. Call store(index, value, mask) for a normal masked register write; override it for read-only or write-one-to-clear registers. Indices are word register numbers.

The adapter binds a SystemC signal to clk. Each accepted CPU request updates bus-visible state, then the kernel advances a low and a high half-cycle of 500 ps each, settling delta cycles. A model therefore receives one positive edge per simulated CPU clock. Browser timers and UI refresh do not drive the device. Each Wasm instance owns an independent SystemC kernel.

This browser build supports clocked SC_METHOD models, signals and delta-cycle evaluation. Coroutine SC_THREAD/SC_CTHREAD models are not supported by the single-threaded host. No SharedArrayBuffer or cross-origin-isolation headers are needed. A small host provides only empty environment/stdin and bounded diagnostic stdout/stderr; it grants no filesystem, network or wall-clock access.

New clocked examples

Timer: +0x00 control (bit 0 enable, bit 1 periodic, bit 2 IRQ enable), +0x04 period, +0x08 elapsed, +0x0C sticky match (write 1 to clear). Zero period becomes one. One-shot stops at the match; periodic mode resets elapsed. The IRQ stays high until software clears the match flag.

Mailbox: +0x00 TX, +0x04 RX (read pops), +0x08 status, +0x0C control (bit 0 enable, bit 1 flush command). Status bits 3:0 give RX depth; bits 8/9 mean full/empty, bit 10 is sticky overflow (write 1 to clear), and bit 11 is pending TX. A staged TX word transfers into the eight-word FIFO on the next enabled clock edge. Inspection never consumes data.

ABI v1

uint32_t mmio_abi_version(void); // required: return 1
uint32_t mmio_size(void);        // required: window size in bytes
void mmio_reset(void);          // required: restore device state
uint32_t mmio_read(uint32_t offset, uint32_t width);
void mmio_write(uint32_t offset, uint32_t value, uint32_t width);
void mmio_tick(uint32_t clocks); // optional: clocks elapsed
uint32_t mmio_inspect(uint32_t aligned_offset); // optional: no side effects

All values use Wasm i32. Width is 1, 2 or 4 bytes; data is little-endian. Read/write run before the accepting rising edge, then mmio_tick(1) runs after it. A write that enables a counter therefore enables counting on that edge. Inspection must never consume FIFOs, acknowledge interrupts or otherwise change device state.

Build and attach

Start with the working SystemC example below. The CMake target links SystemC and exports the device ABI automatically; module authors write neither Wasm exports nor JavaScript glue.

Open Devices, set an unused base such as 0x40000000, and choose your .wasm file. Windows must be word-aligned, 4–65,536 bytes long, outside RAM and the UART/exit window, and must not overlap another device. Using an existing base atomically replaces that instance after validation. Rejected files leave existing devices intact.

Lifecycle and faults

CPU reset resets every attached device. Replacing a device resets only that device and preserves CPU state. Detach returns its address window to unmapped memory. A read/write Wasm trap detaches the failing instance and returns a bus error to SCR1. Other devices remain attached. A tick failure pauses execution with an error. Run bounded code in callbacks; an infinite callback requires restarting the worker. Asynchronous host I/O and DAP/GDB transport are outside this ABI.

Memory timing and interrupts

Devices → Clock and interrupts sets instruction and data acceptance latency from 1 to 32 CPU clocks. A value of 1 accepts a new request on its first edge. Responses are registered on the accepting edge; longer latency inserts request wait states. RAM, built-in registers and custom MMIO share the data setting. Each SystemC device continues ticking during stalls.

The external mask asserts 16 level inputs. Device IRQs are ORed into the same mask using the line selected at attach time; use −1 to disconnect a device. MAX and BASE route these inputs through SCR1's IPIC. MIN has one external interrupt input, driven by the OR of all lines. Software IRQ drives mip.MSIP independently. These controls assert inputs; firmware must enable mie and mstatus.MIE.

For IPIC, select a line in 0xBF6, then write 2 to 0xBF7 to enable an active-high level interrupt. Write any value to 0xBF5 to claim and 0xBF4 to finish service. Enable mie.MEIE (bit 11), set mtvec, and enable global interrupts. Clear the device source before returning with mret. MIN skips the IPIC CSRs.

Select Timer interrupt + mret in the assembly editor after attaching the timer at 0x40000100 on IRQ 0. The handler acknowledges the timer, returns, and stores the interrupt count at 0x1000. The linker places .vectors at 0x1C0 (up to 64 bytes), before the reset entry at 0x200. BASE fixes the low 16 bits of the vector base, and MIN fixes the entire base there. Trap vectors require 64-byte alignment. The example uses a vector trampoline; custom ELFs must supply their own. The GNU assembler symbol SCR1_HAS_IPIC selects the correct setup for each profile. Break on interrupt stops after entry; Continue executes the handler. Exceptions still stop execution.

Override bool irq() const noexcept in a device to expose its level. Keep it asserted until the appropriate status is acknowledged. Shared lines require firmware to inspect each attached source.

Clocked DMA and TLM adapters

Attach TLM DMA engine at 0x40000300, then Load demo. Four words move from 0x1000 to 0x1100; the completed count is stored at 0x1010. Enable diagnostic capture to see all eight read/write transactions.

Offset Register Behavior
0x00 Source Word-aligned RAM address
0x04 Destination Word-aligned RAM address
0x08 Length 1–16,384 words; both ranges must fit RAM
0x0C Control Bit 0: start command; bit 1: IRQ enable
0x10 Status Bit 0: busy; bit 1: done; bit 2: error. Done/error are W1C.
0x14 Progress Completed destination words

Configuration is latched on start. Source, destination, length and another start are ignored while busy; IRQ enable remains writable. Invalid ranges set error without a transfer. Done or error asserts IRQ when enabled. Copy proceeds forward, one read then one write; overlapping ranges have forward-copy semantics. Reset cancels pending work and clears the registers.

Derive a bus master from scr1::ClockedInitiator<N> in scr1/initiator.hpp. Call begin_read(address) or begin_write(address, value) from an SC_METHOD. On a later clock, check response_ready(), inspect response_ok() and response_data(), then call consume_response() before issuing the next request. The helper supports one outstanding 32-bit transaction.

The helper uses an actual TLM-2.0 nonblocking initiator socket. The host target accepts BEGIN_REQ and holds the payload until RAM arbitration completes. BEGIN_RESP implicitly ends the request phase, and TLM_COMPLETED finishes the response. The adapter owns one payload reference until completion or reset; response callbacks run before the next device rising edge. No process waits or coroutine stacks are needed.

The CPU data port has priority at each accepting edge. Devices arbitrate round-robin between completed transactions; an owner holds its pending request until accepted. A busy CPU can starve DMA. Instruction fetch has an independent read port and sees pre-edge RAM contents when a DMA write shares its edge. DMA accesses only naturally aligned RAM bytes, halfwords or words, using the configured data latency; MMIO and out-of-range requests return errors. Reload or detach cancels the removed device's pending request.

scr1::RegisterTarget in scr1/target.hpp adapts TLM b_transport to the same masked register API. The browser adapter uses this target for CPU MMIO. This subset supports little-endian, non-streaming 1/2/4-byte transfers with zero annotated delay. DMI, byte-enable arrays, bursts, multiple outstanding requests and blocking waits are unsupported.

Optional ABI v1 extensions

uint32_t mmio_irq(void);
uint32_t mmio_error(void);
uint32_t mmio_bus_request(uint32_t field);
void mmio_bus_complete(uint32_t status, uint32_t data);

Request fields: 0 valid (0 none, 1 supported, 2 malformed), 1 write flag, 2 address, 3 write data, 4 width encoding (0 byte, 1 halfword, 2 word). Requests must stay stable until completion; status is 1 success or 2 error, with read data valid on success. Malformed requests complete with error. The request and completion exports must appear together. mmio_error reports failure of the last CPU register access; mmio_irq reports a level without side effects. Older ABI v1 modules remain supported.

Build and hosting

nix build
nix develop --command python3 -m http.server 8080 --directory result --bind 127.0.0.1

Serve result/ on any static HTTP host. All CPU simulation, assembly, linking and device execution happen in browser workers; there is no backend. Uploaded files stay in the browser. Relative asset URLs support a GitHub Pages project subpath.

The Pages workflow is manual. Its default run checks and builds a downloadable artifact without publishing. Future publication requires Pages to use GitHub Actions and selecting the workflow's deploy option. Private repository Pages requires an eligible GitHub plan; repository privacy alone does not make the website private.

Read a diagnostic capture

Enable diagnostic mode before the workload. Memory and MMIO events contain cycle number, current PC, address, width, bus data and response. Retirement events contain the completed PC and register changes. Enable fetch logging separately when investigating instruction access errors. Device attach/detach, exit, breakpoint and trap events are recorded independently of diagnostic mode.

The trap panel shows faulting PC, cause and trap value; machine CSRs are sampled directly from SCR1. JSON export includes retained events, registers, RAM window, device state and bus samples. Events have a monotonically increasing sequence number; a dropped-event count makes bounded retention explicit. VCD covers sampled bus signals rather than every internal RTL signal. The bench stops before the trap handler executes.

Assembly reference

GNU as and ld 2.46.0 support standard RISC-V syntax, directives, macros, expressions, relocations and ISA checks. The editor links a real ELF at 0x200. It defaults to .option norvc for predictable instruction widths; add .option rvc for compressed emission. Supported hardware extensions depend on the selected SCR1 profile.

Ctrl/⌘+Enter assembles, Alt+→ steps an instruction, Escape pauses. PC breakpoints stop before a clock; continuing skips the current address until PC changes.

About this workbench

Model and build

Unmodified Syntacore SCR1 RTL is compiled by Verilator and Emscripten into three separate WebAssembly models. Execution and peripherals run in browser workers. Nix pins the source and toolchain; CMake, Ninja and CTest handle building and testing. This page requires no account or backend service.

Scope

MAX, BASE and MIN are upstream recommended configurations. They differ in ISA, pipeline bypasses and optional facilities. CPI includes startup clocks and the configured memory latency; it is not physical chip frequency, area or power. RAM is 64 KiB. JTAG and the core machine timer input remain inactive. MIN begins with zero-initialized two-state model storage, although its hardware register file has no reset.

Comparison stops at 30,000 clocks or 4,096 retirements per profile. Final-state matches require completed runs; trapping and bounded runs are incomplete. Register comparisons use the shared architectural register set.
